DSA ARRAYS — PART 3
Array Manipulation
1. Array Manipulation
Simple explanation:
Array manipulation means changing the elements or their order in an array.
Why?
Many DSA problems require us to add, remove, rearrange, or clean elements.
Example:
[1, 2, 3, 4] → reverse → [4, 3, 2, 1]
Example explanation:
The same elements are still present. Only their positions have changed.
2. Reverse an Array
Simple explanation:
Reversing means changing the array from last-to-first order.
Why?
Reversal is commonly used in array and string problems.
Example:
[10, 20, 30, 40] → [40, 30, 20, 10]
Example explanation:
The last element becomes first, the second-last becomes second, and so on.
3. Reverse Using a Built-in Method
Simple explanation:
A built-in method is a function already provided by the programming language to reverse an array.
Why?
It makes normal programming tasks easier and faster to write.
Example:
[1, 2, 3, 4, 5] → [5, 4, 3, 2, 1]
Example explanation:
The language automatically changes the order of all elements.
4. Reverse by Creating a New Array
Simple explanation:
Create another array and put the original elements into it from the end to the beginning.
Why?
This helps you understand how reversal works without depending on a built-in method.
Example:
Original: [1, 2, 3, 4]
New array: [4, 3, 2, 1]
Example explanation:
Start from 4, then take 3, then 2, and finally 1.
5. Reverse In-Place
Simple explanation:
In-place means changing the original array without creating another array of the same size.
Why?
It saves extra memory and is an important interview concept.
Example:
[1, 2, 3, 4, 5] → [5, 4, 3, 2, 1]
Example explanation:
Swap the first and last elements, then move toward the center and continue swapping.
6. Two Pointers for Reversal
Simple explanation:
Use one pointer at the beginning and another at the end, then move both toward the center.
Why?
It allows us to reverse the array efficiently without another array.
Example:
[1, 2, 3, 4, 5]
First swap 1 and 5:
[5, 2, 3, 4, 1]
Then swap 2 and 4:
[5, 4, 3, 2, 1]
Example explanation:
The left pointer moves right and the right pointer moves left until they meet.
7. Insert an Element
Simple explanation:
Insertion means adding a new element at a specific position.
Why?
Many problems require adding data somewhere inside an array.
Example:
[10, 20, 30]
Insert 15 between 10 and 20.
Result:
[10, 15, 20, 30]
Example explanation:
The existing elements after the insertion position move one position to make space.
8. Insert at the Beginning
Simple explanation:
Adding an element before all existing elements.
Why?
Sometimes a new value must become the first element.
Example:
[20, 30, 40]
Add 10 at the beginning:
[10, 20, 30, 40]
Example explanation:
All existing elements move one position to the right.
9. Insert at the End
Simple explanation:
Adding a new element after the last element.
Why?
Adding at the end is one of the most common array operations.
Example:
[10, 20, 30] → add 40
Result:
[10, 20, 30, 40]
Example explanation:
Nothing else needs to move because the new element goes after the current last element.
10. Delete an Element
Simple explanation:
Deletion means removing an element from an array.
Why?
Real programs and DSA problems often require removing unwanted data.
Example:
[10, 20, 30, 40]
Delete 20.
Result:
[10, 30, 40]
Example explanation:
After removing 20, the elements after it move left to fill the empty position.
11. Delete by Index
Simple explanation:
Remove an element using its position.
Why?
Sometimes the problem gives you an index instead of a value.
Example:
[10, 20, 30, 40]
Delete index 1.
Result:
[10, 30, 40]
Example explanation:
Index 1 contains 20, so 20 is removed.
12. Delete by Value
Simple explanation:
Remove an element by searching for its value first.
Why?
Sometimes you know the value but don't know its position.
Example:
[10, 20, 30, 40]
Remove 30.
Result:
[10, 20, 40]
Example explanation:
First find where 30 is located, then remove it from that position.
13. Delete First Occurrence
Simple explanation:
If a value appears multiple times, remove only its first appearance.
Why?
The problem may specifically ask for only one occurrence to be removed.
Example:
[10, 20, 30, 20, 40]
Remove the first 20.
Result:
[10, 30, 20, 40]
Example explanation:
Only the first 20 disappears. The second 20 remains.
14. Delete All Occurrences
Simple explanation:
Remove every occurrence of a particular value.
Why?
Useful when a value is unwanted everywhere in the array.
Example:
[10, 20, 30, 20, 40, 20]
Remove all 20s.
Result:
[10, 30, 40]
Example explanation:
Every element equal to 20 is removed.
15. Remove Duplicates
Simple explanation:
Remove repeated values so every value appears only once.
Why?
Many problems require an array containing only unique values.
Example:
[1, 2, 2, 3, 3, 4]
Result:
[1, 2, 3, 4]
Example explanation:
The second 2 and second 3 are unnecessary, so they are removed.
16. Unique Elements
Simple explanation:
Unique elements are values that appear only once in an array.
Why?
Sometimes the problem asks specifically for values without repetition.
Example:
[1, 2, 2, 3, 4, 4]
Unique value:
1, 3
Example explanation:
1 and 3 occur once, while 2 and 4 occur multiple times.
17. Remove Duplicates While Keeping Order
Simple explanation:
Remove repeated values but keep the first appearance in its original position.
Why?
Some problems require the original order to remain unchanged.
Example:
[3, 5, 3, 2, 5, 7]
Result:
[3, 5, 2, 7]
Example explanation:
Keep the first 3 and 5. When they appear again, skip them. Then keep 2 and 7.
18. Find Duplicate Elements
Simple explanation:
Find values that appear more than once.
Why?
Sometimes we don't want to remove duplicates; we only want to identify them.
Example:
[1, 2, 3, 2, 4, 1]
Duplicates:
2, 1
Example explanation:
2 appears twice and 1 appears twice.
19. Frequency Counting
Simple explanation:
Frequency means counting how many times each value appears.
Why?
Frequency counting solves many DSA problems involving repeated values.
Example:
[2, 3, 2, 5, 3, 2]
Frequency:
2 → 3 times
3 → 2 times
5 → 1 time
Example explanation:
We go through the array and keep track of how many times each number appears.
20. Frequency Map
Simple explanation:
A frequency map stores each value together with its count.
Why?
It makes counting repeated values much easier.
Example:
[4, 4, 2, 4, 2]
Frequency map:
4 → 3
2 → 2
Example explanation:
The key is the number and the value beside it tells how many times it appeared.
21. Most Frequent Element
Simple explanation:
Find the value that appears the greatest number of times.
Why?
This is a common frequency-based DSA problem.
Example:
[2, 3, 2, 5, 3, 2]
Answer: 2
Example explanation:
2 appears three times, 3 appears twice, and 5 appears once. Therefore 2 is the most frequent.
22. First Occurrence
Simple explanation:
The first occurrence is the first position where a value appears.
Why?
Some problems specifically ask where a value appears for the first time.
Example:
[5, 2, 8, 2, 9]
First occurrence of 2: index 1
Example explanation:
Starting from the left, the first 2 is found at index 1.
23. Last Occurrence
Simple explanation:
The last occurrence is the final position where a value appears.
Why?
Useful when the same value occurs multiple times and we need its final position.
Example:
[5, 2, 8, 2, 9]
Last occurrence of 2: index 3
Example explanation:
There are two 2s. The second one is at index 3, so that is the last occurrence.
24. Array Rotation
Simple explanation:
Rotation means moving elements around while keeping their relative order.
Why?
Rotation appears frequently in array interview problems.
Example:
Right rotation by 1:
[1, 2, 3, 4, 5]
becomes:
[5, 1, 2, 3, 4]
Example explanation:
The last element moves to the front, while the other elements move one position right.
25. Rotate Right
Simple explanation:
Move elements toward the right, with elements leaving the end coming back to the beginning.
Why?
Useful for circular or position-based array problems.
Example:
[1, 2, 3, 4, 5]
Rotate right by 2:
[4, 5, 1, 2, 3]
Example explanation:
The last two elements, 4 and 5, move to the front.
26. Rotate Left
Simple explanation:
Move elements toward the left, with elements leaving the beginning coming back to the end.
Why?
It is the opposite of right rotation.
Example:
[1, 2, 3, 4, 5]
Rotate left by 1:
[2, 3, 4, 5, 1]
Example explanation:
The first element 1 moves to the end, and everything else moves left.
27. Rearranging an Array
Simple explanation:
Rearranging means changing the positions of elements according to a given rule.
Why?
Many interview questions ask you to place certain types of values together.
Example:
Original:
[1, 2, 3, 4, 5, 6]
Even numbers first:
[2, 4, 6, 1, 3, 5]
Example explanation:
The values are divided into two groups: even and odd. Then the groups are placed together.
28. Move Zeros to the End
Simple explanation:
Move all zeros to the end while keeping the other elements in their original order.
Why?
This is a very common array interview problem.
Example:
[0, 1, 0, 3, 12]
Result:
[1, 3, 12, 0, 0]
Example explanation:
The non-zero values remain in the same order: 1, 3, 12. All zeros are moved behind them.
29. Separate Even and Odd
Simple explanation:
Arrange the array so that even numbers come before odd numbers.
Why?
It teaches array rearrangement and partitioning.
Example:
[1, 2, 3, 4, 5, 6]
Result:
[2, 4, 6, 1, 3, 5]
Example explanation:
First collect the even numbers, then place the odd numbers after them.
30. Filtering an Array
Simple explanation:
Filtering means keeping only the elements that satisfy a condition.
Why?
Many array manipulation problems are actually filtering problems.
Example:
Remove all 5s from:
[2, 5, 3, 5, 8, 5]
Result:
[2, 3, 8]
Example explanation:
Check every element. Keep it if it is not 5; skip it if it is 5.
31. Brute Force Approach
Simple explanation:
Brute force means solving a problem using the simplest direct method, even if it is slower.
Why?
It is usually the easiest solution to think of first and helps you understand the problem.
Example:
To find duplicates, compare every element with every other element.
Example explanation:
For each number, check all other numbers to see whether the same value exists.
32. Better Approach
Simple explanation:
A better approach solves the same problem faster or with less unnecessary work.
Why?
Interviewers want you to improve your solution when possible.
Example:
Instead of comparing every pair to find duplicates, remember values you have already seen.
Example explanation:
When a value appears again and you already remember it, you immediately know it is a duplicate.
33. Optimal Approach
Simple explanation:
An optimal approach is an efficient solution that uses the best practical time and memory for the problem's constraints.
Why?
Large inputs can make slow solutions unusable.
Example:
Duplicate detection can often be done in approximately O(n) time using a Set.
Example explanation:
Each value is checked once, instead of repeatedly comparing many pairs.
34. Array Complexity
Simple explanation:
Complexity tells us how the time or memory requirement grows as the array becomes larger.
Why?
It helps us decide whether our solution will work efficiently for large inputs.
Example:
Searching an unsorted array may require checking every element.
For n elements:
O(n)
Example explanation:
If the array doubles in size, the amount of searching may also roughly double.
35. Time Complexity of Reversal
Simple explanation:
Reversing an array requires visiting or changing the elements.
Why?
We need to understand how efficient our reversal method is.
Example:
For:
[1, 2, 3, 4, 5]
we work through the elements to reverse them.
Complexity:
O(n)
Example explanation:
As the array gets larger, the amount of work grows with the number of elements.
36. Space Complexity of In-Place Reversal
Simple explanation:
In-place reversal uses the original array instead of creating another large array.
Why?
It reduces extra memory usage.
Example:
[1, 2, 3, 4] → [4, 3, 2, 1]
Extra space:
O(1)
Example explanation:
Only a few temporary variables are needed, regardless of how large the array becomes.
37. Pattern: Reverse → Two Pointers
Simple explanation:
When you see a reversal problem, think about using two positions: one from the left and one from the right.
Why?
The two pointers allow elements to be swapped from both ends.
Example:
[1, 2, 3, 4, 5]
Left side and right side move toward the middle.
Example explanation:
Swap the outside elements first, then continue inward.
38. Pattern: Remove Duplicates → Set
Simple explanation:
When you need to remember which values have already appeared, think about a Set.
Why?
A Set is designed to store unique values.
Example:
[3, 5, 3, 2, 5]
Unique result:
[3, 5, 2]
Example explanation:
When 3 appears again, we already know it exists, so we skip it.
39. Pattern: Find Duplicates → Set / Frequency
Simple explanation:
To find repeated values, remember previously seen values or count their frequencies.
Why?
It avoids repeatedly comparing every pair.
Example:
[1, 2, 3, 2, 1]
Duplicates:
2, 1
Example explanation:
When 2 and 1 appear again, we know they were already seen.
40. Pattern: Frequency → Map / Dictionary
Simple explanation:
When the question asks "how many times?", think about a frequency map.
Why?
It connects each value with its count.
Example:
[2, 2, 3, 2, 3]
Frequency:
2 → 3
3 → 2
Example explanation:
Each time a number appears, its count increases.
41. Pattern: Move/Rearrange → Filtering / Two Pointers
Simple explanation:
When elements must be moved according to a condition, think about filtering or two pointers.
Why?
These patterns help separate elements efficiently.
Example:
Move zeros:
[0, 1, 0, 3]
Result:
[1, 3, 0, 0]
Example explanation:
First focus on the useful elements, then place the unwanted elements afterward.
42. Pattern: Rotation → Index Manipulation
Simple explanation:
Rotation mainly involves changing where elements are positioned.
Why?
Understanding positions and indexes makes rotation problems much easier.
Example:
Right rotation:
[1, 2, 3, 4, 5]
→
[5, 1, 2, 3, 4]
Example explanation:
The last element moves to the beginning, and the other elements shift right.
43. Built-in Methods vs DSA Logic
Simple explanation:
Built-in methods solve many tasks quickly, but DSA requires understanding what happens underneath.
Why?
Interview questions may ask you to solve something without using a built-in method.
Example:
A language may provide an easy reverse operation, but an interview may ask you to reverse using swaps.
Example explanation:
Knowing the built-in is useful, but understanding the algorithm is more important for DSA.
44. The Main Lesson of Part 3
Simple explanation:
Array problems may look different, but many use the same few patterns.
Why?
Recognizing patterns helps you solve new problems instead of memorizing hundreds of solutions.
Example:
Reverse → Two pointers
Duplicates → Set
Frequency → Map/Dictionary
Remove values → Filtering
Move elements → Two pointers
Rotate → Index manipulation
Example explanation:
When you see a new array problem, first ask: "Which pattern does this problem look like?" That is the important DSA skill.
